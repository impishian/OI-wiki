# OI Wiki Typst 0.15.0 PDF 设计

## 目标

将当前仓库中由 `mkdocs.yml` 导航收录的全部 OI Wiki 文档重新排版为一份完整、可检索、适合屏幕阅读并兼顾双面打印的 PDF。最终构建必须明确使用 Typst 0.15.0，输出文件固定为 `output/pdf/OI-Wiki-Typst-0.15.0.pdf`。

本项目是面向信息学竞赛（OI/ICPC）的中文开放知识库，内容覆盖竞赛介绍、开发工具、编程语言、基础算法、搜索、动态规划、字符串、数据结构、图论、数学、计算几何、专题与杂项算法。当前范围包括 `docs/` 中原有的全部 466 篇 Markdown 文档：`mkdocs.yml` 导航中的 464 篇，加上未纳入网页导航但属于仓库正文的 `edit-landing.md` 与 `intro/docker-deploy.md` 两篇附录；本轮新增的流程设计文档不属于 OI Wiki 正文。

## 方案选择

采用 OI Wiki 官方 `OI-Wiki-export` 的 Typst 导出链作为内容转换基础，并针对 Typst 0.15.0 完成兼容性调整和书籍模板定制。

不采用 Pandoc 直接转换，因为仓库大量使用 MkDocs 扩展语法、提示框、复杂数学公式、代码注释和内部链接，直接转换容易丢失语义。不重新开发 Markdown 转换器，因为官方导出链已经覆盖项目特有语法，复用它能降低 466 篇文章中出现系统性遗漏的风险。

## 内容范围与顺序

- 以 `mkdocs.yml` 的 `nav` 为主要编排顺序，包含其中引用的 464 篇文档；随后按固定顺序追加 `edit-landing.md` 与 `intro/docker-deploy.md` 两篇附录，确保原有 466 篇 Markdown 正文全部出现。
- 保留正文、标题层级、数学公式、代码块、表格、列表、引用、提示框和本地图片。
- 保留能够映射到 PDF 目标的内部链接，并让目录和交叉引用可点击。
- 外部链接保留为可点击链接；纸面环境中不额外生成二维码，以控制页数和视觉噪声。
- 不改写文章观点、算法内容或示例代码，仅做为稳定排版所必需的语法规范化。
- 对网页专属交互内容采用静态、可读的等价表达；`edit-landing.md` 中的脚本和编辑按钮转为“网页编辑入口说明”静态附录，不能把脚本静默丢弃。

## 转换与构建架构

构建分为四层：

1. **导航解析**：读取 `mkdocs.yml`，展开多级导航并生成唯一、有序的文档清单，同时检查重复项和缺失文件。
2. **Markdown 转换**：使用官方 remark/Typst 转换链处理 OI Wiki 扩展语法、LaTeX 数学、代码块、提示框、表格、图片和链接，生成中间 Typst 内容。
3. **书籍模板**：由单独的 Typst 模板控制页面、字体、颜色、标题、目录、页眉页脚、代码、表格、图片和提示框。内容转换层不嵌入零散的版式常量。
4. **编译与验证**：使用本机 `typst 0.15.0` 生成单一 PDF，再执行结构、文字和视觉检查。

转换器、生成内容、字体和临时渲染文件放在构建目录或 `tmp/pdfs/`，最终 PDF 之外的生成物不混入 `docs/` 正文树。

## 视觉与页面设计

### 页面

- 使用 A4 纵向页面，正文区为单栏。
- 内外页边距为双面打印优化，装订侧略宽。
- 大章节从奇数页开始；必要的空白页保留简洁页脚，避免被误认为渲染失败。
- 页码、运行页眉和章节信息保持克制，不与正文争夺视觉层级。

### 字体

- 中文正文使用嵌入式宋体类 CJK 字体，保证长文阅读密度与字符覆盖。
- 中文标题使用辨识度高、不过度装饰的标题字体。
- 拉丁正文与数学字体保持笔画和字面大小协调。
- 代码使用覆盖常见编程符号的等宽字体。
- 构建时显式提供字体路径，不依赖未记录的系统字体回退；最终 PDF 必须嵌入所需字体。

### 颜色与层级

- 以深蓝为主色、青色为强调色，呼应 OI Wiki 的技术主题。
- 正文以高对比度黑灰色为主，彩色只用于标题、链接、提示框和少量导航元素。
- 所有语义在灰度打印时仍可通过边框、图标、标题或明度差区分，不能只依赖颜色。

### 书籍组成

- 封面：书名、项目说明、构建日期、源版本与 Typst 版本。
- 版权与版本页：项目来源、许可证提示、仓库提交号和生成说明。
- 多级目录：包含主要分部、章节和文章标题，条目可点击并带页码。
- 分部扉页：为竞赛、工具、语言、基础算法、搜索、动态规划、字符串、数据结构、图论、数学、计算几何、专题与杂项建立清晰分隔。
- 正文：文章作为稳定的章节单元，保留原有标题层级。

## 元素排版规则

- **代码块**：使用浅色底、细边框、语言标签和自动换行策略；优先保持代码缩进，超长不可断行 token 才缩小字号。代码块不得越过裁切区。
- **行内代码**：使用轻底色或等宽字形，保证中文基线和行高稳定。
- **数学公式**：行内公式不破坏段落行距；独立公式居中并允许跨页前后留白，编号和引用保持一致。
- **表格**：使用重复表头、适度内边距和弱化网格线；超宽表格先压缩列距和字号，再考虑横向页，不能简单裁切。
- **图片**：保持宽高比，优先使用矢量资源；位图不做无意义放大。图像与说明作为整体避免跨页拆分。
- **提示框**：将 note、tip、warning、danger 等语义映射为统一组件，以标题、边框和图标共同区分。
- **引用与脚注**：采用清晰缩进和较弱颜色，脚注须与正文引用双向可定位。
- **链接**：内部链接指向 PDF 目标；外部链接保留 URI 注释，打印时通过样式区分但不显示冗长裸地址。

## Typst 0.15.0 兼容性

- 编译前运行 `typst --version` 并要求精确报告 0.15.0。
- 根据 0.15.0 的迁移要求检查路径、导入、块级元素和模板 API，不以更高或更低版本的成功构建替代验收。
- 对转换器产生的 Typst 源执行一次完整编译；警告按类别汇总，缺图、缺字、未知引用、布局不收敛和内容溢出视为必须处理的问题。
- 允许记录无法影响内容完整性或视觉质量的第三方 SVG 元数据警告，但必须确认对应图片实际渲染正常。

## 错误处理

- 导航引用不存在的 Markdown 时立即失败并报告路径。
- 本地图片缺失、无法解码或路径大小写不一致时立即失败。
- 单篇 Markdown 转换失败时报告源文件、节点类型和可定位上下文，不跳过该文章继续生成“看似完整”的 PDF。
- 数学转换失败时保留可定位诊断；不将原始控制序列静默输出到正文。
- 构建过程中生成的中间文件与最终文件分离；只有所有验证通过后，PDF 才复制到固定交付路径。

## 验证与验收

### 构建验证

- `typst --version` 输出为 0.15.0。
- Typst 完整编译退出码为 0。
- PDF 存在、非空，能够由 `pdfinfo` 和 PDF 解析库重新打开。
- PDF 元数据包含 OI Wiki 标题、构建日期、源提交号和 Typst 版本信息。

### 内容验证

- 导出清单包含 `mkdocs.yml` 导航中的 464 篇文档及两篇明确附录，总计 466 篇原有 Markdown 文档；无缺失、重复或意外新增正文。
- 从 PDF 抽取标题并与导航清单比对，检查主要分部和文章标题覆盖率。
- 搜索转换错误标记、原始模板占位符、缺图替代文本和异常乱码。
- 检查目录、内部链接和页码目标是否存在。

### 视觉验证

- 使用 Poppler 将 PDF 页面渲染为 PNG。
- 至少检查封面、版权页、目录、每个一级分部扉页，以及包含代码、公式、表格、图片、提示框和长链接的代表页。
- 根据编译日志和页面尺寸统计额外检查所有疑似溢出页、异常空白页和横向页。
- 验收标准为：无缺字方框、乱码、内容裁切、重叠、不可读缩放、错误空白页或明显失真的图片；页眉、页脚、页码和章节切换一致。

## 最终交付

- 唯一正式交付文件：`output/pdf/OI-Wiki-Typst-0.15.0.pdf`。
- 保留可复现的构建入口和必要模板，使相同仓库提交在 Typst 0.15.0 下能够重新生成 PDF。
- 最终说明中报告页数、文件大小、源提交号、Typst 版本、验证结果和仍存在但不影响交付的已知限制。

## 非目标

- 不修改 OI Wiki 的算法内容或纠正文中的学术观点。
- 不替换现有 MkDocs 网站构建系统。
- 不在本轮同时生成 EPUB、MOBI、HTML 或拆分卷册。
- 不为所有外部链接生成二维码。
- 不把交互式网页功能原样移植到 PDF。
